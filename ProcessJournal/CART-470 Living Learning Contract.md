**Learning Activities**

1. **Read and respond to the Bret Victor essays** (linked in the contract as course readings).  
   * *Learnable Programming* argues that learners need to see what a program is doing as they change it, that unlabeled numbers are a barrier, and that people should start with something on screen and react to it. It maps closely onto your prototype: sliders should be labelled and show their effect right away.  
   * *Up and Down the Ladder of Abstraction* describes starting with the simplest version, controlling one parameter, stepping up to see patterns, then stepping back down to a concrete example. Use it to structure how you iterate.  
   * Write a short reflection on each (a page or less) and list three design principles you'll apply to your prototype. *(O1, O3)*  
2. **Figma skill-building.** Build one small practice prototype for each tool (interactive component, variable, conditional) before using it in the project, for example a slider that changes a shape's size. *(O1)*  
3. **Analyze Pippin's existing games** (PONGS, Snakisms, the Variations pages) and list which choices a player can change, to decide what your editor needs to expose. *(O2)*

**Final Outcome Expectation:**

1. **Visual prototype(s)**: An interactive visual prototype that will allow the client to experience the user experience and overall feeling of the software  
2. **Practical Prototype(s):** The actual “game” portion, whether or not incorporated with the visual prototype, will be a simplified version of what is pitched.  
3. **Research:** Our final product should not only be a prototype, but should also come with documentation surrounding the ideas behind specific decisions made along the duration of the project.
